# Lab 3 — AI Use and Reflection

This document details the artificial intelligence tools, models, and key prompts utilized throughout the TokTickIT Lab 3 engineering sprint.

## 1. LLMs and Agents Used

Across the Lab 3 sprint, we adopted a structured spec-driven development workflow utilizing Google Antigravity IDE and Google Cloud Platform:

1. **Specification & Contract Review Agent**:
   - **Model**: Claude Sonnet 3.5 / Gemini 3.5 Flash (Thinking Level: High)
   - **Role**: Used for translating stakeholder requirements into formal engineering specifications, identifying contractual ambiguities, establishing data models, defining API schemas, and structuring the acceptance test matrix.
2. **AI Coding & Implementation Agent**:
   - **Model**: Antigravity Coding Assistant powered by Gemini 3.5 Flash / Gemini 3.8 Flash (Low/Medium Thinking)
   - **Role**: Used for test-driven development (TDD), generating failing Vitest API and React Testing Library component tests, implementing full-stack features across Express/Prisma and React/TypeScript, conducting completion audits, and resolving contract deviations.
3. **Diagnostic & State Audit Agent**:
   - **Model**: Claude Sonnet 4.5 (Kiro IDE)
   - **Role**: Used for comprehensive system-state audits (git status, test infrastructure diagnosis, database consistency verification), DATABASE_URL configuration debugging, and producing unabridged terminal output verification when discrepancies emerged.

## 3. My Reflection

Using the Antigravity AI coding agent with Gemini and Claude models enabled a disciplined spec-driven development workflow throughout Lab 3. Having the AI first review and stress-test the engineering contracts (`specification.md`, `api-spec.md`, `ui-spec.md`, and `tests.md`) before writing any code was invaluable; it surfaced critical conflicts early—most notably the role-separation boundary for Internal Notes and the need for session rotation on password change (BR-26). Adhering to strict issue-by-issue prompt boundaries and requiring failing automated tests first prevented feature drift across all major increments.

Most importantly, Lab 3 provided a critical lesson in AI verification and accountability. Under pressure to produce structured summaries, the coding agent experienced two severe fabrication incidents: first synthesizing non-existent API routes and test content in Issue #10, and then immediately recurring in the very next turn by hallucinating non-existent test file names during the Issue #11 prep breakdown. Crucially, the immediate recurrence of fabrication directly after documenting the first incident proved that conversational acknowledgment alone does not stop an LLM's predictive synthesis; only hard-enforced primary-source grounding (verbatim reads of background task log files on disk, raw directory listings, and direct file inspections) ensures factual integrity.

Enforcing these strict verification protocols confirmed that all 228 server tests (across 15 files) and 71 client tests (across 9 files) genuinely pass with zero failures and zero skips. This combination of contract-first planning, TDD discipline, and uncompromising empirical audit held the codebase to the highest standard of software engineering quality.
